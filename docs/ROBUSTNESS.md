# 更新与对话恢复：鲁棒性分析

## 已确认的故障链

1. v0.3 的内嵌控件依赖 app.asar 内三个加载文件。宿主更新覆盖这些文件，sidecar 正常但控件消失。
2. 运行时挂载首次注入时，启动文档可能尚未就绪或已被替换，控件错过挂载。
3. sidecar 的旧环境凭据与最新后台 HTTP 端口不属于同一进程，历史查询返回 401。
4. 会话统计只在内存；后台数据暂时为空、失联或进程重载后，没有独立恢复来源。

## 修复与验证矩阵

| 情况 | 防护 / 恢复 | 验证 |
| --- | --- | --- |
| App 替换 app.asar | 适配器在用户插件目录；默认安装不写 App 归档 | Python 安装/更新测试比较原始字节；2.21.1 实机哈希 |
| 渲染端口 / 窗口变化 | 每 3 秒发现目标并重新连接 | runtime-ui 端口变化回归 |
| 启动文档替换 / 注入错过 | heartbeat 检查 installed/bridge，缺失时重注入 | 启动替换测试；2.21.1 自动挂载 |
| 插件更新但旧控件仍在 | 源码指纹变化时清理并替换 hooks；相同源码幂等 | VM 更新与重复注入测试 |
| 后台凭据与端口变化 | 当前 standalone 凭据匹配由其 PID 持有的 HTTP 端口；失败重新发现并重试一次 | 端口归属/多实例测试；实机旧对话 |
| 切换账号 / 并发请求 | 按账号哈希隔离，检查请求账号与后台代次，合并同会话请求 | 账号切换与旧结果拒绝测试 |
| 重载 / 重启 / 重装 | 持久目录与插件代码分离，恢复每个对话 | 新建 store 恢复；实机补存后禁用轨迹查询验证 |
| 空轨迹 / 样本倒退 | 保留有效样本，标记保存时间 | 空数据、倒退、新请求更新测试 |
| 缓存命中率为 0 | 0 与缺失值分开处理 | cache 与历史恢复测试 |
| 额度 / 列表接口失败 | 指定对话继续独立采集 | quota/list 失败测试 |
| 文件损坏 / 磁盘失败 | 损坏记录忽略，原子替换，实时统计继续并提示未保存 | schema/JSON/路径、并发写入、磁盘失败测试 |
| 远程页面 / iframe | loopback 主 frame、正确 origin、白名单输入、大小和并发限制 | 远程跳转/iframe/协议测试 |

## 持久化边界

只保存模型/状态与白名单数值，不保存正文、标题、邮箱、凭据或原始请求。账号哈希用于隔离，并不意味着不可关联的匿名化。记录不进入 Git 或发行包。

确认当前账号后才读该账号目录。完全离线启动且无法确认账号时不猜测。恢复值是最近保存的真实采样，不能代表失联期间的新请求。若接口从未提供有效时长，无法重建 tok/s。

`node tools/check-live-history.mjs` 补存当前账号仍能从本地接口读取的所有对话，再用禁用轨迹查询的新 collector 检查文件恢复。只输出计数和统计。

## 未来版本的限制

安装目录解耦避免了更新覆盖，但无法保证宿主永远保留 DOM、调试入口、原生 SDK、RPC 与计量字段。变化时内嵌挂载可能失败，后台报告状态并重试；原生面板在其 SDK 仍兼容时可用。SDK/计量协议变化仍需维护适配器。

诊断顺序：`python manage.py status` → 检查健康文件 `checkedAt` 是否新鲜 → 原生侧面板 → 本地日志。不要用旧归档覆盖新版 App；不要直接公开原始宿主日志。
